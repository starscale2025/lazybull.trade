-- THE PROVIDER SEAM + CHAIN --
  ✅ lib/market-data/{provider,index,alpaca,twelvedata,finnhub,yahoo}.ts

-- BREAKERS · DEDUP · CACHE · PROVENANCE --
  ✅ lib/market-data/{health,cache,index,provider}.ts · app/api/status/route.ts
  MECHANISM  Per-provider breaker (3 qualifying fails → 30s open, half-open retry);
             in-flight dedup Map (N identical keys share ONE upstream promise);
             KV-or-memory cache (3s/60s/600s freshness, 24h stale retention for Tier-C
             last-good); every response stamped {provider,tier A/B/C/D,cacheAge,isRealtime}.
  ⇧ CEILING  The dedup Map AND the breaker are per-instance/in-process. On a warm fleet,
             the 3s quote TTL expiring triggers a CROSS-INSTANCE CACHE STAMPEDE — every
             instance re-fetches the same symbol at once — and a downed provider is
             re-discovered instance-by-instance.
  ✚ BREAK IT KV single-flight lock (SET NX on lock:<key>, short expiry): exactly one
             instance refreshes on expiry while the rest serve last-good until it lands.
             Move the breaker counters into that same KV → one shared fleet-wide view of
             provider health.

-- SSE STREAMING TRANSPORT --
  ✅ app/api/stream/quotes/route.ts · lib/streaming/{manager,useLiveQuotes}.ts
  MECHANISM  A thin Node ReadableStream pumps getQuotes every ~2s over a 55s cycle then
             emits bye (under Vercel maxDuration=60) for seamless reconnect, pushing only
             changed prices + hb heartbeats. The browser StreamingManager holds ONE
             EventSource for the union of all subscribers' symbols, fans changed quotes
             out ≤10fps, and falls back to polling after 4 failed attempts. "One upstream
             per symbol" comes from the cache+dedup, not a shared socket — honest ~2–3s.
  ⇧ CEILING  This scales to ~1,000 CONCURRENT viewers on Vercel. Each EventSource pins a
             serverless function for its full 55s cycle; concurrency is bounded by
             Vercel's function limit, not CPU. Beyond ~1k, new streams fail → clients
             degrade to polling.
  ✚ BREAK IT A single always-on edge worker / Durable Object holding ONE upstream Alpaca
             socket, fanning ticks to all browsers. Because the manager AND route are
             already transport-agnostic (documented in both), that worker emits the
             identical `quotes` event shape with ZERO client or route change. This is the
             one place the "no workers on Vercel" constraint must eventually yield — and
             the codebase is already shaped to accept it as a drop-in.

-- P0 RELIABILITY FIXES --
  ✅ route.ts · manager.ts · guard.ts · index.ts (+ 4 named test files)
  MECHANISM  P0-1 per-pump try (a failed fetch never kills the stream) · P0-2 heartbeat on
             its own clock (a slow provider can't fake a stale-reconnect) · P0-3 backoff
             no longer reset by hello (kills the ~1s reconnect hot-loop) · P0-4
             CHAIN_DEADLINE_MS=7s caps the whole chain walk · P0-5 per-IP guard (8
             concurrent / 30-per-min / 50 symbols). Every fix has a unit test.
  ⇧ CEILING  The guard (and breaker) are per-instance → the per-IP cap is really
             per-IP-per-INSTANCE; a client spread across warm instances can exceed 8.
  ✚ BREAK IT Back the guard counters with KV atomic INCR/DECR keyed by IP (same TTL
             window) for a true global ceiling — sharing one KV source of truth with the
             single-flight lock and the breaker.
